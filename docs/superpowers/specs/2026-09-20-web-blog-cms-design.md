# 网页博客后台与数据库

## 验收目标

站长能在博客 `/admin` 内登录、写作、上传图片、保存私有草稿、预览、发布、撤回、回收和恢复内容，管理成员及站点设置；公开页面、搜索、分类标签、RSS 和 sitemap 读取一致的已发布版本。普通访客通过 GitHub 首次登录自动注册为成员，不能自行取得编辑权限。原有评论 AI 初审、人工复审继续使用独立服务。

## 架构决策

沿用 Astro + Svelte 和既有主题，以 Supabase Auth / PostgreSQL / Storage 提供账号、数据与图片。新增 `CMS_ENABLED=true` 的 Node 服务端模式；不启用时仍可构建原 GitHub Pages 静态站。完整版服务器按请求读取公开数据库，不把写作过程塞入 GitHub 提交，也不依赖每次写文章触发 CI。GitHub Pages 不承载服务器，正式切换需要可运行 Node 的托管环境。

数据库未配置时展示准确的安装状态，禁用保存和登录，不用 localStorage 冒充数据库。配置完成后新内容立即可访问。读取失败须显式报错，不回退成可能已撤回的旧内容。

## 数据和权限

- `cms_profiles`：经 Supabase 验证的 GitHub 身份、显示名、角色和停用状态；角色 owner/admin/editor/member。GitHub 数字 ID `105589585` 引导为站长，客户端不能赋予角色。
- `cms_documents`：文章、随记、知识和项目的当前工作副本，含 slug、标题、摘要、Markdown、分类、标签、图片、公开/私有、状态与版本号。
- `cms_publications`：独立的已发布快照，匿名只能读取此表。保存工作副本不更新公开版本。私有内容不进入公开快照。
- `cms_revisions`：不可被客户端篡改的历史版本；恢复产生新草稿版本，不自动发布。
- `cms_settings`：单例公开设置及版本号，站名、简介、作者、头像、关于正文、公告、默认配色和版式；不存 API 密钥。
- `cms_media` / `cms_publication_media`：私有桶的媒体元数据和已发布引用。仅被公开快照引用的图片允许匿名读取。撤回后新请求不能读取。
- `cms_audit_log`：管理和发布操作记录，仅管理员可查。

所有表启用 RLS；写操作由限权 SQL RPC 完成，验证真实身份、角色及乐观版本锁。成员不能改设置或内容；编辑者处理内容；管理员管理非 owner 成员；owner 不可被降权或停用。RPC 使用固定 search_path，显式 grant/revoke。

## 产品范围

后台包含总览、内容列表与筛选、Markdown 编辑器与工具栏、实时安全预览、图片库、版本历史、回收站、站点设置、成员管理、评论审核入口和 JSON/Markdown 备份导出。保存成功后才更新“已保存”；冲突提示重新载入或导出本地文本；离开未保存编辑器有提醒。

公开前台保留现有页面和风格。完整版以数据库为唯一内容来源，静态模式以 Markdown 为来源，两者不混写或自动回退。现有 Markdown 可由导入脚本导入数据库，重复运行不覆盖网页新版本；正式切换前应完成导入与发布。撤回后不能因为源文件仍在仓库而恢复旧公开内容。

登录只支持 GitHub OAuth，回调返回本站后台；正式验收需要用户自己的 Supabase / GitHub OAuth 配置。此前聊天中暴露的旧 AI Key 不使用。

## 验证与上线边界

验证数据库匿名隔离、成员越权、角色管理、草稿不泄露、发布快照、撤回、版本冲突、恢复和媒体权限；验证静态构建及服务器构建；用本地数据库完成保存→发布→公开读取→改草稿→恢复→撤回的真实流程，并检验桌面和手机后台。
