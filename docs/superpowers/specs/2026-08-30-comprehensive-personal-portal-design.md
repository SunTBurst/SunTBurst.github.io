# SunTBurst 综合个人门户与知识平台设计规格

## 1. 文档状态与设计结论

本文是 `SunTBurst.github.io` 第二阶段的总体设计规格，覆盖公开个人门户、参考博客的完整模块、公开与私有知识平台，以及与知识库结合的 AI 能力。第一阶段静态博客仍是可回退的稳定基线。

采用的总体方案是：

1. 公开门户继续部署在 `https://suntburst.github.io`，保留现有 Toy Brick Brutalism（积木粗野主义）视觉语言。
2. 知识平台部署在独立来源，初期使用 `https://suntburst-kb.pages.dev`，具备自定义域名后迁移到 `https://kb.<自定义域名>`。
3. 公开门户与知识平台共享设计令牌、导航语义和公开数据，不共享登录态、浏览器存储或第三方脚本。
4. 服务端能力采用 Supabase（GitHub OAuth、PostgreSQL、RLS、Storage、pgvector、Edge Functions），前端平台保持可替换。
5. 所有外部模块通过明确的功能开关和适配器接入；未配置时提供诚实、可理解的降级界面，不伪造数据。

这不是把参考仓库重新 Fork 回来。允许借鉴其公开界面与交互思路，但身份、文章、素材、数据、密钥、接口、统计账号和自动化必须全部归 SunTBurst 所有。

## 2. 项目目标

### 2.1 核心目标

- 即使文章数量为零，访客也能从首页进入至少三条有意义的浏览路径，并理解“这里是谁的空间、正在关注什么、以后会沉淀什么”。
- 在不虚构经历、项目、文章、访问量和在线状态的前提下，让站点具有持续更新感与探索欲。
- 补齐参考博客现有、历史存在或 README 声明过的主要功能模块，并将不安全或不完整的实现替换为自有实现。
- 建立公开与私有并存、手机和电脑均可使用、多人协作、仅支持 GitHub 登录的知识平台。
- 让 AI 能检索公开知识，也能在严格权限控制下检索登录用户有权访问的私有知识，并为答案给出可追溯引用。
- 保持公开站点可静态部署；任何密钥、私有文档和服务端权限均不得进入 GitHub Pages 构建产物。

### 2.2 成功标准

首次访问者在不阅读文章的情况下，首页必须同时提供至少三条彼此不同、连续两级以上的有效浏览路径，路径可以来自以下行为：

- 通过“从这里开始”了解站点结构；
- 从知识地图进入一个公开主题；
- 查看一个真实项目、当前关注或站点更新；
- 使用随机探索获得一个真实页面；
- 向公开 AI 导览询问本站有什么；
- 订阅后续更新或进入知识平台登录页。

管理员可以：

- 只通过配置和环境变量启用或替换外部服务；
- 使用 GitHub 登录知识平台，审核成员并分配角色；
- 上传、编辑、版本化、检索、公开发布和撤回知识内容；
- 明确区分公开知识索引和私有工作区索引；
- 查看真实运行状态、审计记录和失败原因。

## 3. 范围、基准与非目标

### 3.1 参考基准

第二阶段按“模块能力等价、实现安全独立”理解参考博客，不要求逐行复刻。纳入范围包括：

- 视觉与阅读体验：深浅色、主题动效、自定义指针、点击效果、页面过渡、骨架屏、目录、阅读进度、返回顶部、代码块增强、KaTeX、图片灯箱和响应式布局。
- 内容组织：文章、说说、项目、公开知识、分类、标签、归档、日历、时间线、全文搜索、随机浏览、主题路线、友链和关于页。
- 分发与发现：分页、四类 RSS、sitemap、robots、SEO、Open Graph、分享链接、分享海报和面向 AI 的公开索引。
- 外部能力：AI 总结、文章问答、全站 AI、评论、访问量、站点统计、天气欢迎、随机图片、邮件订阅、音乐、服务状态、GitHub 活动和博客建设统计。
- 参考仓库曾声明但未完整启用的能力，也按本项目的安全边界实现为可用模块，而不是保留空壳。

### 3.2 非目标

- 不复制参考作者的文章、说说、照片、头像、友链、音乐、统计数据和身份信息。
- 不调用参考作者控制的域名、IP、AI、评论、统计、音乐、监控或缓存服务。
- 不把 GitHub Pages 当作安全后端；其中的 `.ts` 文件只能参与构建，不能保护密钥或私有数据。
- 不以虚构示例冒充真实文章、项目、在线人数、访问量、提交活动或知识内容。
- 不承诺端到端加密。私有内容若参与服务端 AI 检索，服务端必然可以处理明文；界面与隐私说明必须如实表述。
- 第一版不追求复杂办公文件的完美解析。首批稳定支持 Markdown、TXT 和文本型 PDF，DOCX、XLSX、PPTX、扫描件与 OCR 在解析链路稳定后扩展。

## 4. 总体架构

```text
访客
  │
  ├─ https://suntburst.github.io
  │    └─ Astro 静态综合门户
  │         ├─ 本地公开内容与构建期索引
  │         └─ 仅调用公开 API 网关
  │
  └─ https://suntburst-kb.pages.dev
       └─ 独立知识应用
            ├─ GitHub OAuth
            ├─ 工作区、编辑器、搜索与管理
            ├─ 普通 CRUD 使用用户 JWT 访问受 RLS 保护的数据接口
            └─ AI、发布和管理操作调用知识平台 Edge Functions

公开 API / 知识 API（Supabase Edge Functions）
  ├─ PostgreSQL + RLS + pgvector
  ├─ Storage + 有时效签名链接
  ├─ AI 供应商适配器
  ├─ 邮件供应商适配器
  ├─ 评论、统计、天气、状态等外部适配器
  └─ 审计、配额、速率限制与内容安全
```

### 4.1 来源隔离

公开门户和知识平台必须位于不同来源，原因是：

- 公开门户会按需加载评论、统计、天气或音乐等第三方能力；知识平台不得加载这些脚本。
- 知识平台的 OAuth 会话不得被公开站点脚本、评论组件或分析脚本读取。
- 一个来源上的 XSS、第三方脚本故障或错误配置不应直接取得另一个来源的私有会话。

两个站点只允许通过普通链接跳转。不能使用共享 `localStorage`、跨域 cookie、URL 中的访问令牌或静默 iframe 来“共享登录”。

### 4.2 仓库结构目标

在尽量不破坏现有 Astro 站点的前提下，逐步收敛为：

```text
apps/
  portal/              公开 Astro 门户（迁移现有 src/ 时再建立）
  knowledge/           独立知识应用
packages/
  design-system/       设计令牌和无状态 UI
  content-contracts/   公开内容与 API 类型
  service-adapters/    服务接口定义，不包含密钥
supabase/
  migrations/          数据库、RLS、索引
  functions/           API、AI、订阅、发布和后台任务
docs/
  operations/          配置、部署、备份和故障处理
```

为降低首批改造风险，先在现有根目录内实现公开门户；只有当知识应用开始编码且共享包确有价值时，再迁移为工作区。避免为了目录整齐提前重构整个项目。

### 4.3 数据访问与服务端权限模型

知识应用不是把所有请求都转发给一个持有管理员密钥的 API：

- 普通文档、成员可见元数据、评论和搜索请求使用 Supabase publishable/anon key 加当前用户 JWT，由数据库 RLS 直接判断权限。
- AI、发布、邀请、角色调整、文件签名和后台任务使用 Edge Functions；函数先验证 JWT，再执行对应的数据库函数或受限查询。
- 用户读取和 RAG 检索不得用 `service_role`。向量检索 RPC 默认采用 `SECURITY INVOKER` 并依赖 `auth.uid()`；若某个操作必须使用 `SECURITY DEFINER`，函数内部必须重新验证调用者、工作区成员状态、角色和目标对象，且固定 `search_path`。
- `service_role` 仅用于没有最终用户会话的受控后台任务，例如清理已撤回的公开索引；不得根据客户端传入的 `user_id`、角色或工作区直接执行读取。
- 客户端传入的 `user_id`、`github_numeric_id`、角色、成员状态和权限范围一律视为不可信。身份只取自服务端验证后的 JWT/OAuth 声明。
- Data API、RPC、Storage 和 Edge Functions 分别进行跨用户、跨工作区、待审核、停用和撤权后的反向测试。

## 5. 公开门户的信息架构

### 5.1 一级导航

桌面端主导航：

1. 首页
2. 文章
3. 知识
4. 项目
5. 动态
6. 实验室
7. 友链
8. 关于

全局工具：搜索、随机探索、AI 导览、收藏/足迹、主题切换、音乐控制、知识平台入口。

移动端将一级导航折叠为可访问的抽屉；AI、搜索和知识平台入口保持一键可达。

### 5.2 首页结构

首页不是文章列表的替代品，而是个人空间的导览页。自上而下采用以下模块：

#### A. 身份与当前状态

- 姓名或公开称呼：SunTBurst。
- 一句可由站点配置修改的个人定位。
- “现在”状态：当前关注主题、所在时区、最近站点更新时间。
- 主操作：开始探索、进入知识库、询问 AI。

未配置详细履历时，只展示已确认的信息和编辑入口，不用套话填满。

#### B. 从这里开始

三至五张入口卡，指向真实存在的内容类型，例如“认识我”“知识地图”“项目台”“最近更新”“随机逛逛”。每张卡说明访客进去能看到什么，而不是只写栏目名称。

#### C. 知识地图

以主题节点和学习路径组织公开知识。没有公开知识时，展示主题框架、收录标准和后续计划；节点必须来自实际配置，不生成虚构条目。

#### D. 当前关注与项目台

- 当前关注：可以是研究问题、正在学习的方向或近期建设任务。
- 项目卡：只列真实项目或“站点建设”本身，显示状态、最后更新和可验证链接。
- “为什么值得看”使用一到两句话解释价值。

#### E. 最近发生

统一活动流可包含：已发布文章、公开知识更新、说说、项目里程碑、站点变更日志和公开 GitHub 提交。每项明确标注来源与时间。

当没有内容活动时，站点变更日志仍可提供真实更新，但不能把构建时间包装成个人活动。

#### F. 随机探索

从真实公开页面清单中抽取内容，支持“换一个”和按内容类型过滤。清单为空时引导至“从这里开始”，不生成不存在的链接。

#### G. AI 导览

首页 AI 只回答公开站点内容和栏目导航问题。默认给出三个可点击问题，例如“这个网站有什么”“从哪里开始”“最近更新了什么”。回答必须引用实际页面。

#### H. 环境与连接

紧凑展示天气、音乐、服务状态、访问统计和订阅。模块未配置时显示真实状态，例如“歌单尚未设置”或“统计仅在同意后启用”，不显示假数值。

### 5.3 内容页面

- `/posts`：文章列表、筛选、分页、搜索和有解释性的空状态。
- `/posts/[slug]`：正文、目录、阅读进度、代码/公式/图片增强、AI 总结、文章问答、评论、分享和相关文章。
- `/posts/[slug]/history`：从公开 Git 历史生成文章版本摘要，不公开提交者邮箱、已删除私密文本或仓库内部信息。
- `/knowledge`：公开知识地图、主题、路径、最近更新和公共 AI 入口。
- `/knowledge/[slug]`：公开发布快照，显示版本、更新时间、来源、引用和“在知识平台中查看”入口。
- `/projects`：真实项目与站点建设记录，可按进行中、维护中、归档筛选。
- `/talks`：短内容流，保留时间、标签、地点/设备等作者主动填写的信息。
- `/now`：当前关注、正在做和近期计划；页面注明更新时间。
- `/changelog`：站点真实变更，不混入虚构个人动态。
- `/topics/[slug]`：跨文章、知识、项目和说说的主题聚合。
- `/archive`、`/categories`、`/tags`、`/calendar`、`/timeline`：多种内容浏览方式。
- `/search`：统一搜索文章、公开知识、项目、说说和站点页面。
- `/favorites`：默认只保存在当前浏览器的收藏与阅读足迹；使用共享设备时可一键清除，未经登录不得上传。
- `/lab`：可控的小工具、可视化和实验功能；实验必须标注状态与数据边界。
- `/friends`、`/about`、`/privacy`、`/status`、`/subscribe`：关系、身份、隐私、运行状态与订阅。

## 6. 零文章状态的内容原则

“可以没有帖子”不等于可以没有信息。零文章状态必须满足：

- 首页仍有身份说明、导航、当前关注、站点项目、知识主题框架、更新记录和可用工具。
- 文章页说明未来收录什么、如何分类、如何订阅；不展示空白网格或假的推荐文章。
- 项目页至少允许展示“SunTBurst 个人门户”这一真实建设项目，但必须使用真实进度。
- 知识页可以先展示公开知识结构和发布规则；不能把空节点伪装成已有资料。
- 活动流只合并真实事件，并允许用户隐藏 GitHub 活动。
- 随机探索只在已有公开路由中抽取。
- 所有时间、数量、状态来自可验证数据或明确的站点配置。

## 7. 模块矩阵与降级行为

每个模块分别记录“实现状态”和“运行状态”，不能用一个开关混淆代码是否完成与线上是否可用。

实现状态由测试与交付清单维护：

- `planned`：尚未完成。
- `implemented`：代码和配置已完成，但尚未通过全部验证。
- `verified`：已通过该模块的自动化、浏览器、安全和降级测试。

运行状态由站点配置决定：

- `disabled`：完全不渲染，也不加载资源。
- `preview`：保留入口、说明用途和配置状态，不调用外部服务。
- `enabled`：通过自有配置和适配器工作；健康检查失败时自动回退到有意义的静态界面。

`preview` 不能算作线上功能完成。内容为空时，模块可以达到“实现已验证、线上呈现真实空状态”，但不能宣称相应的 AI、评论或外部服务已有真实业务数据。

| 模块 | 正式实现 | 未配置或失败时 | 关键边界 |
| --- | --- | --- | --- |
| 深浅色与主题 | 本地主题令牌、系统偏好、手动选择 | 使用系统主题 | 不依赖外部主题脚本 |
| 指针、点击与过渡 | 尊重 `prefers-reduced-motion` 的本地效果 | 自动关闭动画 | 不阻断阅读和键盘操作 |
| 阅读增强 | TOC、进度、返回顶部、代码复制、KaTeX、灯箱 | 保留纯 HTML 正文 | 所有内容先消毒 |
| 预取与离线缓存 | 仅在良好网络下按悬停/意图预取公开页面，可清理缓存 | 完全关闭仍可正常导航 | 尊重 Save-Data，不缓存私有页和第三方响应 |
| 全站搜索 | 构建期生成公开索引，客户端分词与筛选 | 提供栏目导航 | 私有知识绝不进入索引 |
| 收藏与阅读足迹 | 浏览器本地保存公开路由和阅读位置 | 关闭后不留记录 | 明示本机数据，可导出/清除，不存正文 |
| 随机探索 | 从构建期真实路由清单随机选择 | 回到“从这里开始” | 不调用未知随机站点 |
| 随机图片 | 自有精选清单与可追溯授权信息 | 使用本地图形封面 | 不热链不明版权图片 |
| 分享 | 原生分享、复制链接、平台链接和本地海报模板 | 复制链接 | 不上传正文到第三方 |
| 评论 | Waline 适配器，后端和域名归用户 | 显示“评论暂未开放” | 明示隐私、审核与登录方式 |
| 文章访问量 | 优先使用自有聚合 API；可兼容 Waline 浏览量 | 隐藏数值 | 不用假 0 代替未知 |
| 站点统计 | 自托管或用户自有 Umami | 展示不追踪说明 | 同意策略、IP 匿名化、知识站禁用 |
| 天气欢迎 | 默认固定城市；访客主动授权后才取其位置 | 展示站主城市或隐藏 | 不使用隐式 IP 定位 |
| 音乐 | 用户自有或明确授权的音频/播放列表 | 歌单未设置说明 | 不代理盗版音源、不自动播放 |
| 服务状态 | 服务端健康检查与缓存后的公开摘要 | 显示“状态暂不可用” | 不暴露内部 URL、日志和版本细节 |
| GitHub 活动 | GitHub 公共 API 的构建期或服务端缓存 | 隐藏活动流 | 不在浏览器放 Token |
| 外部主页内容 | GitHub 为默认适配器，可选 Bilibili 等本人账号的公开内容 | 隐藏对应卡片 | 只在配置本人账号后启用，不用聚合代理泄露访客信息 |
| 个人在线状态 | 主人主动心跳或手工状态，带过期时间 | 显示“状态未知”或隐藏 | 不从访客、位置或第三方活动暗中推断 |
| 博客统计 | 从构建产物与 Git 历史计算页面、字数、更新 | 只显示可计算项 | 与访问统计分开标注 |
| 文章公开历史 | 构建时提取文章相关 Git 版本与摘要 | 隐藏历史入口 | 删除邮箱、内部路径和非公开 diff |
| 友链 | Issue 表单收集、人工审核、结构化数据合并；可选受控截图预览和 AI 表单引导 | 展示申请规范 | 禁止 Issue 内容拼接 shell，AI 不得自动批准或直接写仓库 |
| 邮件订阅 | 双重确认、退订、最小数据表和邮件适配器 | 保留订阅说明与不可用状态 | HTTPS、限流、签名令牌、不得明文发全文到未知 IP |
| RSS | 文章、说说、知识更新、全站更新四类 | 空 feed 仍合法并有说明 | 只包含公开内容 |
| SEO 与 AI 索引 | sitemap、OG、JSON-LD、`llms.txt` | 基础 meta | `llms-full.txt` 只含明确公开内容 |
| 搜索引擎主动提交 | 由构建任务向 IndexNow 等已配置服务提交公开变更 URL | 仅保留 sitemap | 密钥仅在 CI，提交清单不含私有或预览路由 |
| WebMCP/智能体导航 | 实验室内提供只读的公开搜索、导航和页面摘要能力 | 浏览器不支持时隐藏 | 不提供写入、登录或私有知识工具 |
| AI 总结 | 发布或缓存后的文章摘要，标注 AI 生成 | 使用作者描述或隐藏 | 不伪装成作者原文 |
| 文章 AI | 只检索当前文章及公开引用 | 回退到文章搜索 | 每个结论给段落引用 |
| 全站 AI | 公开索引 RAG、流式回答、推荐问题 | 回退到统一搜索 | CAPTCHA、限流、预算和安全过滤 |
| 公开知识 AI | 只检索 `published_*` 快照 | 回退到知识搜索 | 与私有索引物理/逻辑分离 |
| 私有知识 AI | 登录、成员校验、RLS 过滤后的 RAG | 明确错误并保留普通搜索 | 禁止跨工作区召回 |

### 7.1 功能开关

公开配置只能包含无密钥信息，例如：

```ts
type FeatureState = "disabled" | "preview" | "enabled";
type FeatureImplementationStatus = "planned" | "implemented" | "verified";

interface PublicFeatureConfig {
  comments: FeatureState;
  analytics: FeatureState;
  weather: FeatureState;
  randomImages: FeatureState;
  newsletter: FeatureState;
  music: FeatureState;
  serviceStatus: FeatureState;
  publicAI: FeatureState;
  articleAI: FeatureState;
  knowledgeAI: FeatureState;
}
```

构建时必须校验：生产构建中，处于 `enabled` 的模块若缺少公开端点、站点 ID 或必要配置，必须失败；只有本地开发可在明确警告后自动降为 `preview`。不能产生部分可用、暗中报错的线上页面。

实现清单为每个模块记录负责人、实现状态、所需凭据、测试证据和线上状态。用户尚未提供凭据的模块进入“上线阻塞清单”；不能用 `preview` 代替最终验收。

## 8. 知识平台设计

### 8.1 登录与成员准入

- 唯一登录方式是 GitHub OAuth。
- OAuth 使用 Authorization Code + PKCE、随机 `state`、固定回调地址和最小身份 scope；不申请仓库权限，不持久保存 GitHub provider token。
- 第一次登录只创建平台账号，不自动加入任何工作区，也不自动获得任何知识内容。
- `pending` 是逐工作区的邀请或加入申请状态。`owner` 或 `admin` 根据服务端验证的 GitHub 身份审核并激活成员。
- 身份关联使用不可变的 GitHub numeric ID，用户名只用于显示，避免改名后身份漂移。
- 默认角色：`owner`、`admin`、`editor`、`viewer`。
- 邀请在服务端绑定目标 GitHub numeric ID；邀请链接本身不能被另一个 GitHub 账号领取。
- 工作区角色决定操作上限，文档可见性和 ACL 决定对象范围；ACL 只能收紧或在角色上限内授权，不能突破角色上限。
- OAuth 回调地址采用固定 allowlist；禁止任意 `redirect_to`。

“GitHub-only”同时适用于公开评论身份：默认 Waline 仅开放 GitHub OAuth，关闭匿名、邮箱密码和其他社交登录。若未来选择 Giscus，也只使用 GitHub 身份，不建立第二套公开账号体系。

#### 8.1.1 权限真值表

| 操作 | viewer | editor | admin | owner |
| --- | --- | --- | --- | --- |
| 读取 `workspace` 文档 | 是 | 是 | 是 | 是 |

| 搜索/AI 检索 | 仅限可读文档 | 仅限可读文档 | 仅限可读文档 | 仅限可读文档 |
| 评论可读文档 | 是 | 是 | 是 | 是 |
| 新建文档 | 否 | 是 | 是 | 是 |
| 编辑正文 | 否 | 本人或显式 write ACL | 本人或显式 write ACL | 本人或显式 write ACL |
| 提交公开发布申请 | 否 | 对可编辑文档 | 对可编辑文档 | 对可编辑文档 |
| 审核公开发布 | 否 | 否 | 是，但不能借此读取未授权私有正文 | 是，但不能借此读取未授权私有正文 |
| 邀请/停用 viewer、editor | 否 | 否 | 是 | 是 |
| 管理 admin | 否 | 否 | 否 | 是 |

`admin` 和 `owner` 默认只能管理私有文档的标题、所有者、状态等必要元数据，不能读取正文。初版不实现“紧急访问”；未来若确需 break-glass，必须单独审批、限时授权、通知文档所有者并完整审计。

### 8.2 主要界面

- `/login`：GitHub 登录、隐私说明和准入规则。
- `/pending`：显示待审核状态，不泄露工作区信息。
- `/app`：个人工作台、最近访问、待办审核和导入状态。
- `/app/workspaces/[id]`：工作区内容、成员和设置。
- `/app/documents/[id]`：编辑、预览、版本、引用、评论和 AI 侧栏。
- `/app/search`：权限过滤后的全文与语义搜索。
- `/app/graph`：知识关系图和反向链接。
- `/app/inbox`：手机快速收集文本、链接和文件。
- `/app/admin`：成员审批、角色、配额、审计、失败任务和公开发布审核。

界面支持窄屏；编辑、搜索、收集和 AI 问答必须在手机上可完成。复杂关系图在手机上可切换为列表视图。

### 8.4 可见性与公开发布

文档内部可见性只有 `private` 和 `workspace`：

- `private`：仅作者和显式授权用户可见。
- `workspace`：具有相应工作区权限的成员可见。

公开发布不能把原文档就地切换成 `public`。必须经过以下流程：

1. 编辑者选择一个不可变版本并提交公开发布申请。
2. 系统生成独立预览，执行敏感信息检查和链接检查。
3. 管理员审核标题、正文、附件、引用与许可证。
4. 系统复制为 `published_documents` 快照并单独生成 `published_chunks`。
5. 发布函数更新只读公开清单，并以带签名、可重放保护的 webhook 触发 GitHub `repository_dispatch`。
6. GitHub Actions 只使用权限受限的公开读取凭据获取发布清单并重建门户；不得把 `service_role` 放进 Pages 工作流。
7. 构建产物记录公开清单版本与校验和，部署完成后回报构建版本。
8. 撤回时先把快照标记为不可公开，删除 `published_chunks` 和公开附件清单、清理服务端缓存，再触发同一重建流程。
9. 定时对账任务比较数据库公开清单和线上构建版本，自动补偿 webhook、构建或清缓存失败；后台明确显示“撤回等待重新部署”，不能提前宣称已从线上移除。

这样可以防止后续私有编辑被意外同步到公开站点。

撤回只能移除当前可控的线上版本和缓存，不能保证删除已被浏览器、搜索引擎、第三方缓存或互联网归档保存的副本。敏感内容不得依赖事后撤回来补救。

### 8.5 导入与版本

- 第一批：Markdown、TXT、文本型 PDF、网页剪藏和纯文本快速记录。
- 文件先检查扩展名、MIME、magic bytes、大小、校验和和重复内容，再存储。
- 解析与嵌入使用 PostgreSQL `pgmq` 持久队列和定时调度器；任务包含幂等键、租约、超时、并发上限、重试上限和死信状态，不能把一次 Edge Function 调用当作可靠队列。
- Markdown/TXT 在严格大小限制下由受限处理器解析；PDF 即使可提取文本也属于不可信文件，必须由隔离解析 Worker 处理。解析 Worker 只取得单个对象的短期签名 URL，不持有数据库或 Storage 管理密钥，并限制出站网络。
- 界面显示排队、处理中、成功、部分成功、失败与死信原因，并允许有权限的成员安全重试。
- 文档正文每次保存携带 `base_version_id` 并生成不可变版本。若基线已变化，服务端返回冲突并提供版本比较，禁止静默覆盖他人修改；标题、标签等轻量元数据同样使用版本号或 ETag。
- 附件通过短期签名 URL 访问，Storage bucket 默认私有。
- 后续办公文件和 OCR 使用隔离的解析服务，不在主 API 进程直接执行高风险文件解析。

初版删除采用软删除：文档进入回收站 30 天，期间从搜索和 AI 索引移除；到期后幂等清理正文、附件、片段、向量和缓存。工作区删除前必须转移所有权或由 owner 二次确认。用户可以导出其有权访问的内容并申请删除账号；审计事件至少保留 1 年，备份中的删除按备份保留周期自然到期并在隐私说明中披露。

## 9. AI 与 RAG 设计

### 9.1 四个独立作用域

1. `article`：当前公开文章。
2. `public_site`：公开门户全部索引。
3. `public_knowledge`：经审核的公开知识快照。
4. `workspace`：当前用户在指定工作区内有权访问的私有知识。

四种作用域使用不同端点、缓存键、索引过滤器、会话保留策略和配额。公开请求永远不能通过传参切换到 `workspace`。

### 9.2 私有问答流程

```text
验证 Supabase 会话
  → 校验成员为 active
  → 解析目标 workspace
  → 由 RLS 筛选可访问文档
  → 只在筛选后的 chunks 中做向量/全文混合检索
  → 对候选片段二次权限校验
  → 组装最小必要上下文
  → 调用 LLM
  → 返回答案、逐条引用和权限范围
  → 记录不含正文的审计事件
```

回答引用至少包含文档标题、版本、片段定位和可访问链接。若证据不足，回答必须明确“知识库中没有足够依据”，不能用模型常识伪装成库内结论。

### 9.3 模型适配

服务端使用兼容接口而非绑定单一模型：

- `AI_BASE_URL`
- `AI_API_KEY`
- `AI_CHAT_MODEL`
- `AI_EMBEDDING_MODEL`
- `AI_EMBEDDING_DIMENSIONS`

允许分别配置聊天和嵌入供应商。更换嵌入模型时必须建立新索引版本并后台重建，不能在同一向量列中混用维度或模型。

### 9.4 公开 AI 防滥用

- Cloudflare Turnstile 或同等级人机验证。
- IP/会话哈希限流，原始 IP 不进入长期业务表。
- 单次问题、上下文、输出、每日预算和并发上限。
- 重复问题缓存，但缓存键必须包含索引版本和作用域。
- 提示注入防护：知识片段作为不可信数据，不能覆盖系统权限或工具规则。
- 公开 AI 无任何写入知识库、调用管理接口或读取私有索引的工具。

### 9.5 私有上下文、引用与缓存

- 私有 AI 答案缓存默认关闭。
- 若工作区以后主动启用私有缓存，缓存键至少包含 `user_id + workspace_id + membership/ACL revision + document version set + model/index version`，不能只按问题或工作区复用。
- 成员停用、角色变化、ACL 修改、文档更新/删除、模型或索引版本变化时立即使相关缓存失效。
- 引用由服务端依据本次实际召回的 chunk 生成，并在响应前再次验证权限；模型只能选择引用编号，不能自行生成可点击文档 URL。
- 私有片段发送给聊天或嵌入供应商前，工作区管理员必须明确启用对应供应商并确认其数据保留、训练和地域条款。
- 私有问题、片段和回答不得进入普通请求日志、错误追踪正文或第三方分析系统。

### 9.6 对话保留

- 公开 AI 默认短期或不持久保存正文，只保留聚合指标和错误信息。
- 私有 AI 的对话保留期可由工作区配置；用户可删除自己的对话。
- 任何用于模型改进或人工分析的二次使用必须单独征得同意。

## 10. 外部服务与适配器

### 10.1 原则

- 前端只知道公开端点、公开站点 ID 和功能状态。
- 密钥只存于 GitHub Actions secrets、Supabase secrets 或对应服务的安全配置中。
- 每个服务适配器提供 `health`、超时、重试上限、缓存、错误分类和熔断行为。
- 所有外部请求使用 HTTPS 和固定域名 allowlist。
- 禁止将文章全文、订阅者列表或对话内容发送到未列明的端点。

### 10.2 推荐默认组合

| 能力 | 推荐默认实现 | 可替换项 |
| --- | --- | --- |
| 身份与数据库 | Supabase | 兼容 PostgreSQL + OAuth 的自建后端 |
| 知识应用托管 | Cloudflare Pages | 其他支持独立来源的静态/边缘平台 |
| Edge API | Supabase Edge Functions | Cloudflare Workers / 自建 API |
| 公共人机验证 | Cloudflare Turnstile | hCaptcha 等 |
| 分析 | 自有 Umami | Plausible 或完全关闭 |
| 评论 | 用户自有 Waline | Giscus 适配器 |
| 邮件 | Resend 适配器 | Postmark / SES |
| 天气 | Open-Meteo，默认固定城市 | 其他合规天气源 |
| AI | OpenAI-compatible 服务端适配器 | 任意兼容聊天与嵌入供应商 |

上述是实施默认值，不是不可替换的供应商承诺。真实上线前仍需用户创建账号、配置域名、提供合法密钥并确认数据处理条款。

## 11. 安全与隐私

### 11.1 必须满足的边界

- 仓库、Git 历史、构建日志、`dist/`、source map、RSS、sitemap、搜索索引和 `llms*.txt` 中不得出现密钥、私有文档、私有附件 URL 或私有对话。
- Supabase `service_role`、AI、邮件、GitHub 和分析管理密钥只存在服务端。
- CORS 分别 allowlist 公开门户和知识平台来源，不使用 `*` 处理带凭据请求。
- 知识平台使用严格 CSP，不加载评论、统计、天气、音乐、广告和非必要第三方脚本。
- Markdown/HTML 在服务端或构建期消毒；禁止任意脚本、事件属性、危险 URL 和未授权 iframe。
- 关键管理动作要求近期登录，可选二次确认，并写入审计表。
- 邀请、确认订阅、退订和公开预览使用有时效、不可猜测、单用途令牌；数据库保存令牌哈希。
- 备份分别覆盖数据库和对象存储，并定期验证恢复流程。

### 11.2 隐私页面

公开隐私说明至少列出：评论、分析、天气定位、AI、订阅、GitHub 活动和第三方服务；标明数据、目的、保留时间、关闭方式和联系渠道。

知识平台隐私说明额外列出：GitHub 身份字段、文档存储、AI 供应商、管理员可见范围、审计、备份、删除和导出。不能把“私有”描述成管理员或服务端不可见。

### 11.3 数据保护目标

- 数据库与私有对象至少每日备份，保留 30 天；向量可重建，但权限、版本、审计和原文件必须备份。
- 数据库备份与 Storage 对象备份分开执行，并复制到与生产密钥隔离的恢复位置。
- 初期生产目标为 RPO 不超过 24 小时、RTO 不超过 8 小时；若所选套餐无法满足，知识平台不得标记为正式生产可用。
- 每季度完成一次真实恢复演练，保存恢复时间、对象数量、校验和和权限回归测试结果，而不是只确认“备份任务成功”。

## 12. 可靠性与降级

- 门户核心导航、静态内容、搜索索引和主题不依赖运行时 API。
- 任何单一外部模块失败都不能阻塞页面正文或首页主要导航。
- 客户端请求设置超时、取消和可重试错误；不对权限错误自动重试。
- 健康状态注明最后检查时间，过期结果显示为“未知”，不继续显示绿色。
- AI 不可用时回退到普通搜索和相关内容，不展示无限加载动画。
- 知识导入失败保留原始文件和可重试任务，不生成半成品公开快照。
- 公开发布、撤回、成员授权和删除采用幂等服务端操作。

## 13. 性能、可访问性与 SEO

- 首页首屏不等待 AI、评论、天气、音乐、统计或状态接口。
- 第三方模块在接近视口或用户交互后才加载；知识平台不加载这些模块。
- 图片提供尺寸、现代格式、懒加载和本地占位；随机图片也必须有版权来源与替代文本。
- 核心页面满足键盘操作、可见焦点、语义标题、表单标签、错误提示和颜色对比要求。
- 动画尊重 `prefers-reduced-motion`，音乐禁止自动播放。
- 每个公开页面有唯一标题、描述、canonical、OG 信息和结构化数据。
- 空栏目可以被索引，但 meta 描述应准确说明当前状态，不制造已有大量内容的印象。

## 14. 测试策略

### 14.1 公开门户

- 单元测试：配置校验、内容聚合、路由清单、随机选择、搜索、RSS、订阅令牌和适配器降级。
- 构建测试：所有静态路由、sitemap、四类 RSS、公开 AI 索引和资源引用。
- 安全扫描：参考作者域名/账号/IP、密钥模式、私有标记、未知外链、危险工作流和构建产物泄漏。
- 组件测试：零内容、少量内容、外部服务关闭、超时、错误和恢复。
- 浏览器测试：桌面与手机导航、主题、搜索、随机探索、分享、订阅、无障碍键盘路径。
- 性能检查：首页关键指标、第三方延迟加载和 JavaScript 预算。

现有“禁止一切浏览器网络请求”的测试应改成显式能力 allowlist：默认仍禁止网络，只有状态为 `enabled` 且域名在对应适配器 allowlist 中的请求可以通过。继续永久禁止参考作者的域名、ID 和固定服务器信息。

### 14.2 知识平台

- RLS 矩阵：每个角色对每张表的读、写、更新、删除；跨工作区和待审核成员必须失败。
- OAuth：只允许 GitHub、固定回调、账号改名、撤销授权和会话过期。
- 文件：伪造 MIME、超限、重复、恶意 HTML、损坏 PDF 和解析超时。
- 发布：预览、审核、发布、更新、撤回、缓存清理和搜索/AI 索引同步。
- RAG：公开/私有索引隔离、权限变化后召回、引用准确性、无证据回答、提示注入和配额。
- 审计：成员、权限、发布、删除、导出和管理操作完整记录。
- 恢复：数据库与 Storage 的备份恢复演练。

### 14.3 验收环境

至少在以下环境完成验证：

- 本地生产构建；
- GitHub Pages 预览或正式地址；
- Cloudflare Pages 知识应用预览；
- 桌面 Chromium 与 WebKit；
- 360px 和 390px 触控手机视口；
- 减少动画和键盘无鼠标模式。

空内容 fixture 下必须自动验证：首页至少有三条不同探索路径，每条可连续访问两个有效页面；所有入口返回成功、无死链、无虚构数量，随机探索只命中构建期真实路由。移动端端到端测试必须完成 GitHub 回调、文本编辑、文件上传、搜索和 AI 问答，并检查无横向溢出、主要触控目标不小于 44px。受控测试环境下，首页和知识平台入口页的 Lighthouse 目标为 Performance 不低于 90、Accessibility 不低于 95、CLS 不高于 0.1。

## 15. 分阶段交付

阶段划分用于降低风险，不缩减最终范围。每一阶段必须可部署、可回退、可独立验收。

### 阶段 1：有内容感的公开门户

- 重构首页、导航和真实空状态。
- 新增“从这里开始”、知识地图、项目台、当前关注、最近发生、随机探索和变更日志。
- 恢复低风险的主题、指针、过渡、阅读增强、统一搜索、收藏/足迹、网络感知预取、分享、文章历史和博客构建统计。

### 阶段 2：公开外部模块

- 评论、访问量、Umami、天气、精选随机图、合法音乐、服务状态、GitHub/外部主页活动和主人主动在线状态。
- 邮件双重确认、退订和运营说明。
- 功能开关、适配器健康检查、隐私与失败降级。

### 阶段 3：公开 AI

- 文章摘要与文章问答，以及实验室中的只读 WebMCP 导航能力。
- 全站 AI 导览和公开知识 AI。
- 流式回答、引用、推荐追问、Turnstile、限流、预算与缓存。

### 阶段 4：知识平台基础

- 独立应用、GitHub OAuth、待审核准入、成员与角色。
- 工作区、Markdown/TXT/文本 PDF、编辑、版本、附件、全文搜索和手机收集。

### 阶段 5：知识公开与协作

- 发布审核与独立公开快照。

- 公共门户构建/缓存更新机制。

### 阶段 6：私有与公开 RAG

- 混合检索、权限过滤、引用、会话与配额。
- 公开和私有索引隔离、模型切换和嵌入重建。
- 提示注入、越权、撤权后缓存和泄漏测试。

### 阶段 7：完整验收

- 桌面/手机、无障碍、性能、SEO、隐私、安全和恢复测试。
- 外部服务逐项健康检查和关停演练。
- 真实域名、密钥、回调、邮件域名和监控配置清单。

## 16. 实施假设与需要用户提供的外部条件

本设计先按以下假设实施：

- GitHub 用户名为 `SunTBurst`，公开门户继续使用现有用户站点仓库。
- 知识平台首次上线使用 Cloudflare Pages 实际分配且可用的独立域名；`suntburst-kb.pages.dev` 是首选名称但受平台可用性约束，未来有自定义域名再迁移。
- GitHub 首次登录默认待审核，不允许任意 GitHub 用户自动加入。
- Supabase 是初版后端，AI 使用服务端 OpenAI-compatible 适配器。
- 外部模块先实现代码、配置和预览降级；需要真实账号或收费资源的模块，在用户提供相应凭据后才能宣称线上可用。

最终上线前需要用户自行拥有或授权以下外部资源：

- Cloudflare 账号与 Pages/Turnstile 配置；
- Supabase 项目；
- GitHub OAuth App；
- AI 聊天与嵌入服务密钥；
- 邮件发送服务和已验证发件域名；
- 可选的 Umami、Waline、音乐和自定义域名。

任何缺失资源都只影响对应模块，不阻止公开门户核心内容上线。

## 19. 完成定义

只有同时满足以下条件，第二阶段总体目标才算完成：

1. 公开门户即使零文章也具有清晰身份、真实内容结构和连续浏览路径。
2. 本规格追踪矩阵中的功能均达到实现状态 `verified`，线上运行状态为 `enabled` 或由用户明确选择 `disabled`；不能用 `preview` 或未说明的空壳代替。
3. 外部模块全部使用 SunTBurst 自有配置，失败时不影响核心站点。
4. 知识平台支持 GitHub-only 登录、审核准入、多人角色、公开/私有内容、手机/电脑访问、版本、搜索和发布审核。
5. 公开与私有 AI 均可用，回答带引用，且通过跨工作区、撤权和构建产物泄漏测试。
6. 隐私说明、备份、审计、配额、部署和故障运行手册完整。
7. 本地、预览和线上环境完成自动化与人工浏览器验收，且不残留参考作者域名、账号、密钥或内容。
