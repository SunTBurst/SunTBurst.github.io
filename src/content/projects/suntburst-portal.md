这个项目只记录已经完成和正在进行的站点工作。访问量、在线人数和未启用服务不会被写成成果。

## 为什么建设这个门户

最初的博客已经能发布文章，但访客必须先知道自己要找什么。这个项目进一步把文章、说说、知识、项目、更新和工具连接起来：即使文章数量不多，访客仍然可以沿主题、时间或建设过程继续探索。

## 已经具备什么

- 首页提供三条起步路线、知识地图、项目书架、最近值得看和随机探索；可复用内容优先于建设日志展示。
- 全站搜索、收藏与足迹、内容日历、时间线、RSS、天气、随机画片、GitHub 公开活动、公开知识问答、声音空间、站点数据和构建状态已经可以使用。
- 友链页区分真实互换关系与精选站外书签，并使用公开 GitHub Issue 接收不含敏感信息的申请，不再保留无内容的死胡同页面。
- 今日漫游按利雅得日期每天稳定生成一条“知识—实践—工具”三站路线，为回访提供变化，同时不读取定位、记录或个人画像。
- 文章和说说详情具备阅读进度、代码复制、图片查看、分享和返回顶部。
- GitHub Pages 会在 `main` 分支更新后自动构建并发布静态站点。
- 天气已按主动同意、固定坐标和失败降级原则启用；声音空间采用零外部请求的本地合成；AI 导览基础版只检索公开索引并提供来源，外部大模型、评论、访客统计和邮件订阅仍未启用。

## 当前结构

1. **内容层**：文章、说说、知识、项目和更新保存在仓库的 Markdown 文件中。
2. **索引层**：构建时生成统一公开索引，供搜索、主题、时间线和随机探索使用。
3. **页面层**：Astro 生成静态 HTML；Svelte 只负责确实需要交互的局部组件。
4. **发布层**：GitHub Actions 完成安装、构建和 Pages 部署。
5. **浏览器层**：收藏、足迹和主题状态只保存在当前浏览器，不上传个人数据。

## 重要设计决定

- 公开站点保持静态优先，避免为了少量交互引入账户和数据库。
- 公共博客与未来私有知识平台分开部署，公开页面不能读取私有资料。
- 外部服务必须先具备明确的数据来源、失败回退和隐私说明，再从“接入说明”升级为“已启用”。
- 已启用的外部请求必须通过构建审计，当前只允许天气页面访问固定的 Open-Meteo 端点。
- 随机图片采用带授权信息的本地精选清单，不依赖不明版权或不稳定的外部图片接口。
- GitHub 活动在构建期生成脱敏快照，页面不向 GitHub API 发送访客请求，失败时使用带时间标记的备用快照。
- 站点数据只统计公开内容和构建事实；构建状态不替代实时健康检查，不声称未实施的在线率。
- 声音空间只在访客主动操作后由浏览器本地合成，不保存偏好、不记录播放行为，也不连接外部音源。
- 公开知识问答先用本地确定性检索落实来源和“当前未知”；真实模型必须等服务端密钥、限流、预算和权限隔离具备后再接入。
- 友链不能用自有账号或模板站点凑数；未建立真实关系时保留诚实空位，同时用已核对书签维持页面价值。
- 每日路线只由日期和公开候选列表确定，同一天对所有访客一致；它是内容编排，不冒充个性化推荐。

## 下一步如何验收

- 评论需要完成 GitHub 身份验证、内容审核和无脚本回退验证。
- 统计需要验证访客同意、匿名化、拒绝后零请求以及数据删除方式。
- AI 回答必须限定在已发布内容，附带可打开的来源链接，并对未知问题明确说不知道。
- 私有知识平台需要验证 GitHub 登录、成员权限、资料隔离、审计记录和受控公开发布。
- 每次上线继续执行类型检查、全部测试、生产构建和真实页面访问检查。
