> **版本撤回通知（2026-09-12）：1.2.0+4 已撤回，暂勿使用该版本；修复与验证完成后再更新本页。**

这篇教程适用于微信沟通助手 Windows 测试版 1.2.0+4。它是个人测试软件，默认采用“生成草稿—人工确认—复制到微信—人工发送”的方式。

想了解我为什么做这款工具，以及我在 Vibe Coding 中怎样负责需求、取舍和验收，可以先读[项目介绍文章](/posts/wechat-assist-vibe-coding/)。

软件不会因为保存了模型或联系人配置就自动发送消息。“自动回复”是独立的实验功能，默认关闭。当前真实微信读取、填入和发送尚未完成全部验收，请不要把它用于无人值守发送。

## 一、打开软件

解压或复制程序包时，请保留整个 `release` 文件夹。Windows 版除了 EXE，还需要同目录中的 DLL、`data`、资源文件和插件，不能只单独复制一个 EXE。

进入解压后的 `release` 文件夹，双击 `wechat_assist.exe` 打开软件。当前主界面有四个入口：

- **回复**：选择联系人、填写意图、生成和修改候选；
- **联系人**：搜索联系人并维护联系人画像；
- **我的资料**：填写自己的背景和表达偏好；
- **设置**：配置连接、自动回复、回复规则和高级功能。

右上角的“打开当前微信辅助”用于打开独立悬浮窗。“全部停止”用于停止当前运行中的自动化状态。日常使用可以先留在主窗口完成配置。

独立分发包默认把配置、数据库和画像等本机数据保存在当前 Windows 用户的 `%LOCALAPPDATA%\WeChat Assist`，不会因为从快捷方式、解压目录或其他工作目录启动而换到另一套数据。程序更新时可以替换完整 `release` 文件夹，不要把用户数据复制进程序目录。

## 二、先填写“我的资料”

进入“我的资料”，按实际情况填写自己的身份背景、常用语气、表达偏好和需要长期保留的信息，然后点“保存资料”。每次保存会形成新的资料版本。

建议只填写会影响回复质量的内容，例如：

- 你的工作角色和常见沟通对象；
- 偏好的称呼、句子长短和正式程度；
- 哪些场景要先说结论，哪些场景要更委婉；
- 不希望模型擅自承诺的事项。

不要在资料中填写 API Key、密码、银行卡号等敏感凭据。API Key 有单独的系统安全存储入口。

## 三、维护联系人画像

进入“联系人”，搜索并选择要沟通的对象。联系人库、最近会话和已经建立画像的联系人是不同概念，列表中的“其他联系人（类型待确认）”也不应直接理解为微信好友。

打开联系人后，可以维护称呼、关系、沟通偏好、注意事项等画像信息，再点“保存画像”。手工填写的内容由你决定；如果以后使用 AI 生成画像建议，也应先审阅再合并。

同一个联系人可以根据本次谈话切换回复模式，不需要把联系人永久固定成某一种模式。

## 四、配置模型服务

进入“设置 → 常用设置”，找到模型服务入口；也可以打开“高级设置”，选择“API Key”。弹窗标题为“模型连接”。

需要填写的项目包括：

1. **Provider**：选择模型服务；
2. **模型名称**：填写或保留该服务对应的模型；
3. **API Key**：首次配置时填写；已经保存后可以留空保留原值；
4. **兼容地址（可选）**：使用 Provider 默认地址时留空，自定义兼容服务时再填写。

填好后点“保存并检查”。保存成功与模型健康检查是两个状态：配置可能已经写入，但服务地址、模型名、Key 或权限不匹配时，健康检查仍会报错。

### DeepSeek

Provider 选择“DeepSeek”。新建配置的默认模型以当前程序显示为准。填入 DeepSeek 对应的 API Key，默认地址无需手工修改，然后点“保存并检查”。

### Kimi Code 订阅

如果使用 Kimi Code 订阅提供的 Key，Provider 必须选择“Kimi Code（订阅）”。它与“Kimi China”“Kimi Global”开放平台不是同一个凭据体系，Key 和 API 地址不能混用。

若出现 HTTP 401，先核对所选 Provider 是否与 Key 的来源一致，再检查地址和账号权限。不要只凭 401 判断 Key 已失效。

### OpenAI、Kimi 开放平台及自定义兼容服务

按 Key 的实际来源选择对应 Provider。只有服务方明确提供 OpenAI 兼容接口时，才填写“兼容地址（可选）”。切换 Provider 或地址后应使用该作用域对应的 Key；软件会按 Provider 和规范化 API 地址隔离保存凭据。

### Ollama

选择“Ollama”，确认本机服务已经启动，再填写实际模型名称。本地服务的 Key 可以留空，具体以本机 Ollama 配置为准。

### LM Studio

先在 LM Studio 中启动本机服务并加载聊天模型，再打开软件的“模型连接”窗口，将 Provider 选择为“LM Studio”。软件进入 LM Studio 配置后会自动读取本机模型：

1. 等待“正在读取 LM Studio 本机模型…”结束；
2. 在“本机模型”下拉框中查看发现结果，模型旁会显示“已加载”或“已下载”；
3. 选择用于对话生成的模型，优先选择已经加载的聊天模型，不要选择 embedding 模型；
4. 如需重新读取，点击提示为“刷新本机模型”的刷新按钮；
5. 确认“已发现 N 个可用对话模型”后，点“保存并检查”。

如果 LM Studio 服务已经连接但没有可用的对话模型，界面会保留“模型名称”输入框，可以手动填写模型标识。自动读取失败也不会清掉已经手工填写的名称；先检查 LM Studio 服务和兼容地址，再决定是否手动保存。

当前测试环境使用 LM Studio 0.4.24+1、1234 回环服务和 `google/gemma-4-e4b`。应用的生产回复引擎已经通过健康检查，并在 180 秒预算内基于合成对话生成三条候选回复。这项结果证明本地模型回复链路可用，不代表真实微信对话已经完成验收。

## 五、配置微信上下文

进入“设置 → 常用设置”的微信连接区域，按界面引导完成本机只读上下文配置。需要刷新时，使用页面内的刷新入口。

干净分发包不包含可选的 `wx_key.dll`。微信上下文初始化依赖使用者自行已有的、受信任且与本机微信版本兼容的连接组件；如果没有这一组件，不能把“解压并打开软件”理解为微信已经连接。不要从来源不明的网站下载 DLL，也不要为了连接而强制降级微信。

软件的目标是读取本机已登录微信的必要上下文，不因刷新而自动发送消息。当前版本的真实微信读取仍有未完成验收的部分；如果页面提示未识别、读取不完整或联系人不能唯一确认，应停止本次自动关联，手工选择正确联系人，不要根据相似名称猜测。

悬浮窗本身不会触发第二套解密刷新。需要更新本机快照时，回到主程序操作。

## 六、生成第一版回复

进入“回复”：

1. 确认软件已经读取到可用的联系人和对话上下文，再选择本次要沟通的联系人；
2. 选择“情绪导向”“工作导向”或“通用兼顾”；
3. 在“我想表达”中写下真实意图。可以只写要点，也可以留空让助手先给建议；
4. 发起生成，等待候选回复；
5. 选择更接近自己想法的一条。

模型配置成功只是生成条件之一。没有读到可用的联系人上下文时，软件不会让模型补写一段假聊天；请先修复上下文连接或刷新，再开始生成。

写意图时，优先说明目标和边界。例如：

> 告诉供应商资料必须在周三前提交。语气保持合作，但不要让对方理解成时间可以再商量。

如果系统判断信息不足，可能先提示需要补充的问题；补充后再生成即可。“暂不需要回复”也可能是正常结果，不等于模型故障。

## 七、用自然语言逐版修改

选中一条候选后，在“对这条回复提出具体修改要求”中写要求，例如：

> 更简短一点，但保留对进度的明确要求。

> 不要太像正式函件，改成微信里自然一点的说法。

> 先回应对方的困难，再说明我方不能接受延期。

系统会保留 V1、V2 等版本。需要回看时，可以切换历史版本，也可以点“回到 Vx 继续修改”。每次修改尽量只说清本轮最重要的变化，方便判断新版本是否真的更好。

满意后点候选旁的复制按钮。出现“已复制，可到微信粘贴”后，回到微信检查联系人、内容和附件，再由本人发送。

## 八、使用悬浮窗

在主窗口点“打开当前微信辅助”打开独立悬浮窗。如果当前对象未绑定，可以在悬浮窗中使用识别入口；遇到多个候选时必须手工选择，未识别时保持原绑定不变。

悬浮窗和主窗口使用同一套回复业务与当前生效规则。它适合边看微信边修改草稿，但仍应在发送前核对：

- 当前联系人是否正确；
- 事实、数字、时间和承诺是否准确；
- 语气是否符合关系和场景；
- 复制后的文字是否完整。

## 九、编辑“回复规则”

进入“设置 → 回复规则”，可以查看和编辑完整业务提示词。编辑会先形成草稿；试用与正式生效相互隔离。

建议顺序是：

1. 修改规则并保留草稿；
2. 用合成场景试用，检查输出是否符合预期；
3. 确认后正式应用；
4. 如果效果变差，恢复默认或回到历史版本。

正式应用只影响之后的新请求。已经生成的候选和正在处理的请求不会被静默改写。主窗口与悬浮窗读取同一份生效规则。

## 十、自动回复与 OpenClaw

“设置 → 自动回复”标明为“实验功能 · 草稿形态（人确认后发送）”。默认保持关闭。按联系人登记规则也不等于系统已经取得真实发送能力；发送能力未验证时，结果应落为草稿，复制确认后由人发出。

如需立即停止，点“立即停止自动回复”或主窗口右上角“全部停止”。重新恢复前，程序还会检查全局开关、模型、连接器和发送能力。

OpenClaw 是可选配置，需要另行安装并运行 OpenClaw Gateway。OpenClaw Companion 不能代替 Gateway；如果电脑上只有 Companion，就暂时跳过本节，继续使用 DeepSeek、Kimi、LM Studio 等普通 Provider。

配置前，先在独立 WSL 环境中启动 OpenClaw Gateway，为微信回复建立专用 reply Agent，将其工具权限全部设为 deny，并启用 Chat Completions endpoint。随后进入“高级设置 → OpenClaw 地址”，填写本机可访问的 Gateway 地址（通常为 `http://127.0.0.1:18789/v1`）、专用 Agent ID 和 Gateway Token，再点“保存并检查”。

Gateway Token 会单独进入系统安全存储，不与云模型 API Key 共用。OpenClaw 的端点也与普通 Provider 隔离。保存 OpenClaw 后，回复路由优先使用 OpenClaw；重新保存普通 Provider 配置可以切回对应 Provider。

当前测试电脑没有实际运行的 OpenClaw Gateway，因此尚未完成真实连接验收。“保存并检查”成功前，不要把已填写配置理解为已经联通。

## 十一、备份与恢复

在“设置 → 常用设置”或“高级设置”的备份入口中，可以导出本机加密备份。当前复合备份覆盖：

- 本机业务数据库；
- 已确认的本人资料和联系人画像；
- 当前生效的业务规则。

微信快照、解密密钥、API Key、Wechaty Token、OpenClaw Gateway Token 和运行配置不进入该备份，需要分别保留和重新配置。

恢复会先在暂存区校验；完成后按提示关闭并重新启动软件。恢复前请先停止正在运行的生成或自动化任务。

## 十二、当前版本的验收边界

1.2.0+4 已完成 DeepSeek、Kimi Code 和 LM Studio 的合成资料三候选生成验证。当前仍有 7 项既有的 Windows 安装环境检查未通过，因此不能写成全量测试通过。

以下内容仍不属于已完成验收：

- 真实微信完整历史读取；
- 真实窗口的全部交互流程；
- 自动填入和真实发送；
- 无人值守自动回复；
- 真实 OpenClaw Gateway 接入。

遇到能力状态不明确时，继续采用人工确认、复制和手工发送流程。

接口配置参考：[LM Studio 开发文档](https://lmstudio.ai/docs/developer)、[OpenClaw HTTP 接口](https://docs.openclaw.ai/gateway/openai-http-api)、[OpenClaw 工具权限](https://docs.openclaw.ai/tools)。
