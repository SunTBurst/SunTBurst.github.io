这篇文章介绍 Windows 微信沟通助手的完整使用流程，并说明正在准备的开源源码范围。它帮助你整理资料、参考当前沟通上下文、生成回复草稿并逐版修改；最后由你复制文字，回到微信核对后手动发送。软件不会把“生成成功”理解成“已经发送”。

> **当前状态：图文教程已公开，源码仓库仍为私有审阅状态，尚未对外开放。** 本文先分享使用方法与合成示意图；源码下载入口将在仓库正式开放后更新。

![回复工作流示意](/images/wechat-assist-open-source/workflow.svg)

本文的流程图和两张界面图用于说明操作；界面内容来自合成测试资料，不含真实联系人或聊天，不作为实际微信连接证据。

## 用途和开源范围

拟开放的源码包含资料与联系人画像、三种回复模式、模型适配、回复候选、自然语言逐版修改、主窗口与悬浮窗界面、合成测试资料和离线测试。个人资料、微信数据库、解密快照、备份、诊断导出、API Key、Gateway Token 和真实聊天记录不属于公开内容。

源码包不附带微信连接所需的 `wx_key.dll`，也不附带任何模型文件或个人配置。首次微信取钥仍需用户自备并合法取得所需组件，完成组件校验后，再按页面提示由本人登录；不能把开源源码包理解成可以独立完成首次连接的完整安装包。

审阅仓库为 [SunTBurst/wechat-assist-open-source](https://github.com/SunTBurst/wechat-assist-open-source)，目前仅授权账户可访问，普通访客暂时无法下载源码。下文的教程可以直接阅读；源码构建说明与公开下载入口将随仓库开放一起提供。

## 首次准备和资料

在 Windows 上完成构建后启动程序。首次打开时，选择新建资料、接续已有资料或迁移旧布局。接续时确认当前资料根确实属于你要继续使用的那一份，程序不会静默换用另一份资料。

进入“我的资料”，填写自己的工作背景、常用称呼、表达偏好和不希望擅自承诺的事项。这里不要填写 API Key、密码或支付信息。进入“联系人”，搜索并选择对象，维护称呼、关系、沟通偏好和注意事项。联系人库、最近会话和已建档联系人是不同概念，遇到相似对象时要手工确认。

## 模型及微信连接

模型配置入口是“高级设置 → 模型连接”弹窗。选择 Provider，填写模型名称、API Key，必要时填写兼容地址，然后点“保存并检查”。保存成功和健康检查成功是两个状态；检查失败时，先核对 Provider、地址、模型名称和账户权限。凭据应只保存到本机安全存储，不要写进源码、截图或公开 issue。

使用本机模型时，先启动对应服务并加载模型，再回到弹窗选择模型。LM Studio 的发现入口仍然保留，但正式使用的本地模型尚未确定，实际效果也尚未验收。

微信连接使用独立的“微信连接”页面。已有连接可以先检查并刷新；首次取钥时先点“开始连接准备”，按提示完整退出微信、重新打开并停在登录页；等助手提示连接组件准备好后，再由本人登录。组件校验、密钥验证和上下文刷新是不同阶段，任何阶段失败都应按当前页面的错误和恢复动作处理。

微信连接只读取本机已登录微信可提供的限定上下文，不代表拥有完整聊天历史，也不代表获得发送权限。若联系人不能唯一确认、消息不完整或来源仍显示未验证，应先停止关联并手工选择正确对象。

## 回复与逐版修改

进入“回复”，确认联系人和上下文状态后，选择“情绪导向”“工作导向”或“通用兼顾”，再写下本次表达意图。意图可以是几条要点，例如“说明资料必须在周三前提交，语气保持合作，但不要让对方以为截止时间还能顺延”。

![合成工作台示意](/images/wechat-assist-open-source/compact-workbench.png)

生成后先比较候选内容，再选择最接近自己想法的一条。选中候选后，用自然语言提出具体修改，例如“更短一些，保留截止时间”，或“先回应对方的困难，再说明不能接受延期”。每次修改会形成新的版本，便于回看差异。

历史版本用于查看和对照；如果要继续修改，应回到最新版本后再提出修改要求，不要把任意旧版本直接当作当前编辑对象。满意后点复制，回到微信检查联系人、事实、数字、时间、附件和承诺，最后由本人手动发送。软件不会自动填入或自动发送这段文字。

![合成逐版修改示意](/images/wechat-assist-open-source/compact-revision.png)

图中的“模拟填入”是测试界面文字，真实日常流程仍使用复制后人工发送。修改要求还可以选择仅用于本次、当前联系人或全局风格。

## 回复规则

在“设置 → 回复规则”查看和编辑完整业务提示词。先保存草稿、用合成场景试用，确认后再正式应用；必要时可恢复默认或历史版本。规则只影响之后的新请求，已生成的候选不会被静默改写。

## 悬浮窗和停止关闭

从主窗口打开当前微信辅助，可以边看微信边生成和修改草稿。悬浮窗与主窗口使用同一份资料、联系人和生效规则。出现多个联系人候选时必须手工选择，未识别时不要根据相似名称猜测。

生成、修改或刷新过程中需要中止时，使用当前页面的“停止当前操作”；需要暂停全部辅助时使用“全部停止”；实验自动回复页也有单独停止入口。关闭悬浮窗前，程序会尝试保存当前草稿；如果后台操作尚未结束，先等待停止状态或使用页面提供的放弃修改并关闭入口。

## 备份

使用设置中的备份入口导出本机业务资料。备份文件仍然是个人数据，应放在受控位置。不要把备份、微信原库、解密快照、密钥、诊断包或含真实聊天的截图提交到公开仓库。提交问题时请使用合成联系人、合成消息和脱敏日志。

当前正式人工流程包括资料维护、联系人选择、三种回复模式、候选生成、自然语言逐版修改、版本保留、复制和人工发送。自动回复默认关闭，仍属于实验能力，不能据此理解为无人值守发送已经验收。LM Studio 的正式本地模型尚未确定，实际效果未验收。
